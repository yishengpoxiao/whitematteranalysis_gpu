# Startup and processing optimization — 2026-10-14

The release continues to use `slicer/WMAGPU/dist/WMAGPU-Installer.zip`.
Sources and the installer bundle include the following changes.

## Changes

- Load WMA computation modules and GPU backends on first attribute access.
  Opening Slicer workflow pages does not import PyTorch, SciPy, or Matplotlib.
  Cache a successful shared environment check across pages. CPU distance helpers
  no longer import an unused torch module.
- Reuse pairwise registration's length-filtered moving and fixed polydata across
  iterations. Cache keys include the input object, VTK modification time, minimum
  length, and maximum length. Downsampling and fiber resampling still execute
  each iteration with the same random seeds and line ordering.
- Compute the inverse reference-volume affine once per tract-to-volume command,
  rather than once per point. Both density and scalar-measure conversion use it.
- Batch scene grouping/combining and pause rendering. Defer the merge checklist
  until the scene batch ends, suspend table painting while updating rows, and
  deduplicate nodes shared by multiple selector classes. Stop the refresh timer
  during widget cleanup. Restore scene and render state after exceptions.

## Bounded measurements

These are single measurements on a shared Linux workstation, using cached files.
They establish the removed overhead, not an end-to-end pipeline speed guarantee.
Windows/macOS timing and native application validation remain outstanding.

| Workload | Before | After | Scope |
| --- | ---: | ---: | --- |
| First Pipeline widget initialization | 3.2262 s | 0.0215 s | Fresh Slicer 5.2.2 processes; empty scene |
| Initialization of all five workflow widgets | 3.2365 s | 0.0350 s | Excludes Slicer launch, viewport rendering, and data loading |
| Pairwise input preparation, 15 iterations | 3.1118 s | 0.2720 s | Two 40,000-fiber inputs, 20 input points/fiber; optimizer excluded |
| Density conversion, 50,000 points | 1.9792 s | 0.7063 s | Includes file I/O; negative and positive out-of-bounds points |
| FA conversion, 50,000 points | 1.9965 s | 0.7112 s | Includes file I/O; same input and reference affine |

The preparation benchmark samples 2,000 fixed and 1,000 moving fibers at 10
points/fiber. Fixed and moving arrays match exactly at every iteration. Its
approximately 11.4x reduction applies only to preparation; registration optimizer
time was deliberately excluded. Retaining two filtered polydata copies increases
host-memory use for the lifetime of the registration object.

The tract-to-volume comparison uses a nonidentity reference affine and checks
exact equality of the density and FA volumes. Matrix inversions decrease from
50,000 to one for each command. OPENBLAS_NUM_THREADS=1 and OMP_NUM_THREADS=1 were
used for this bounded comparison, not configured globally or in the extension.

The Slicer test creates 800 hidden tractography nodes with the merge widget
active, processes GUI events during creation, and groups them into one folder.
There are no checklist refreshes inside the batch and one after each completed
batch. Creation, checks, grouping, and refresh take approximately 5.69 s combined.
There is no pre-change timing for this workload.

## Validation

- A fresh-interpreter import test confirms that package import and GPU settings
  do not load computation libraries. Accessing CPU helpers and WMA I/O/filtering
  still does not import torch, SciPy, or Matplotlib.
- Five registration tests cover every CLI preset, invalid custom schedules,
  CPU/CUDA affine/rigid/nonrigid transforms, groupwise output, inverse transforms,
  and preprocessing reuse. Samples and NumPy RNG state match the previous path
  after sample-size/point-count changes, length-limit changes, input replacement,
  and in-place VTK point modification followed by `Modified()`.
- Four core tests cover atlas construction/reload/labeling, groupwise registration,
  single-file MRML, and explicit unavailable-CUDA errors.
- Seven GPU registration tests ran: six passed and one optional Triton test was
  skipped because Triton was unavailable. Numerical objective/transform checks,
  CUDA out-of-memory fallback, and optimizer cleanup passed.
- Linux Slicer 5.2.2 checks cover retained transforms, affine/B-spline HDF5
  save/reload, Pipeline output, checked-node merge methods, parent transforms,
  overlapping node classes, 800-node batches, and merge-failure cleanup.

Scientific dependencies now load when an operation first needs them. A first
computation or CUDA availability check may still take time. Long registration
calculations still run on Slicer's main thread; this change accelerates page setup
and repeated preparation, but does not move the optimizer to a background worker.
