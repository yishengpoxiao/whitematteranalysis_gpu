# GPU acceleration development record (2026-10-11)

Reference source: `/data/software/whitematteranalysis`. Working repository:
`/data/yijie/whitematteranalysis`. The handoff and optimization notes in the
`wma-GPU` workspace were reviewed alongside the original registration code,
existing backends, validation scripts, and Slicer modules.

## Implementation

Affine registration in `RegisterTractography.objective_function` now calls the
fused `gpu.registration.objective_value`. Moving fibers are uploaded once, and
transformed coordinates remain on CUDA for distance/probability computation,
avoiding an intermediate GPU-to-NumPy-to-GPU round trip. The public
`transform_fiber_array` still returns NumPy arrays. Float64, VTK matrix construction,
coordinate accumulation order, CPU entropy reduction, and optimizers retain the
existing algorithm.

`tests/test_gpu_registration.py` compares against the original VTK/NumPy functions,
covering three transform modes, three tile sizes, fused versus separate objective
values, and the registration class entry point. CUDA tests explicitly skip when
CUDA is unavailable.

This commit also includes GPU source and five CLI entry points identified as
uncommitted work in the handoff. Existing ORG shell, tract-to-volume, egg-info,
and build changes are excluded.

## Performance

Single RTX 4090, float64, 10 points per fiber. After warmup, old and new paths were
alternated for 20 runs each; medians are reported. `perf_counter` includes
synchronization before return. Inputs are RandomState(42) normal samples, sigma=10,
and a nontrivial 15-parameter affine transform. The old path uses a pre-change
snapshot of `gpu/registration.py`.

| fixed × moving | Previous GPU path | Fused GPU path | Time reduction |
|---|---:|---:|---:|
| 100 × 100 | 1.077 ms | 0.999 ms | 7.2% |
| 3000 × 1000 | 10.092 ms | 9.894 ms | 2.0% |

These are objective-function timings, not equivalent speedups for the entire
registration workflow. Distance tensors still dominate large matrices; subsequent
work should prioritize profiling real data.

## Scope at this checkpoint

Nonrigid B-spline transform application still runs through VTK on CPU; this round
does not claim GPU acceleration for that part. The existing self-contained `.sx`
archive was not rebuilt. The local Slicer source symlink uses the new code;
archives on other machines remain at the previous version. The stub harness needs
to be rebuilt for the six-module layout and must inspect errors caught inside
setup, rather than checking only whether setup raises an exception.
